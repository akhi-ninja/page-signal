# Hosted API location and source reporting

The private `/admin` dashboard keeps AI attempt quotas separate from authenticated HTTP request metadata. Existing usage counters supply distinct accounts with AI attempts over the last 30 UTC dates, including failed attempts. New daily aggregate records cover verified signed-in calls to `/api/ai/extract` and `/api/ai/jobs`, including query operations, job polling/actions, HTTP errors and average server processing time. These are not provider-call counts, unique people, documents or npm installs. The reported response duration excludes metadata persistence time. Unauthorized requests and background worker callbacks are excluded.

Country and region come only from `x-vercel-ip-country` and `x-vercel-ip-country-region` when running on Vercel production/preview. No city, raw IP, full URL, path/query, document content, user agent, cookie or credentials are retained in this table. Non-Vercel locations are Unknown. VPNs and server-to-server traffic can identify an intermediary location. Origin/referrer hostname is a caller-reported hint and is never used for authorization; on hosted browser calls it normally identifies PageSignal itself. It does not discover which external company uses a package. Invalid/missing metadata stays Unknown.

Aggregation is per UTC day, account, environment, location/source, endpoint, method and status. Existing admin GitHub-account allowlist authorization protects all reports; regular community responses contain no aggregate report. Only top 50 location/source/endpoint groups are displayed, with deterministic ordering. Account counts across groups overlap. Preview and production reports are separate. Deleting an account cascades its metadata rows. Records older than the last 30 UTC dates are pruned on writes/admin reads and by the existing daily authenticated retention cron; access queries always exclude old dates even if physical cleanup fails. Database backups have separate retention. No historical location is inferred or backfilled. Existing account/auth metadata and hosting logs remain separate.

The additive table is created idempotently on the first authenticated write or authorized admin read, following the community registration schema pattern; the application database role needs CREATE TABLE permission. Reporting failures leave the original extraction/job response unchanged; an admin sees reporting unavailable. Failed aggregation can undercount, so this is operational reporting, not a billing ledger. No cross-user content cache, npm install hook or remote package telemetry is added. The public privacy notice describes collection.

## Earlier traffic in Vercel

Open the page-signal project in Vercel. Use Logs/Requests and filter production plus `/api/ai/extract` or `/api/ai/jobs` for API traffic. Available request records and time ranges depend on the project's plan and retention. Function execution region is the server location, not the caller's country. Web Analytics country/referrer reports, if Web Analytics was enabled, describe instrumented website visits rather than all API callers; Google Analytics has the same distinction. Historical incoming Origin/country headers cannot be recovered from PageSignal quota counters. No paid analytics upgrade or Log Drain is enabled by this change.

References: https://vercel.com/docs/headers/request-headers, https://vercel.com/docs/cli/logs, https://vercel.com/docs/analytics/web-analytics-api.
